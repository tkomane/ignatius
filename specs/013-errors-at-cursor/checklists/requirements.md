# Requirements Quality Checklist: Errors that point at the problem

- [x] The feature name and branch are explicit.
- [x] The primary user journey is independently testable.
- [x] User stories are prioritised by user value.
- [x] Acceptance scenarios use Given, When, Then language.
- [x] Multi-statement and UTF-8 behavior is specified.
- [x] Missing, stale, and unavailable context are specified.
- [x] The specification states what must not happen automatically.
- [x] Accessibility and presentation-loss requirements are explicit.
- [x] Security and redaction boundaries are explicit.
- [x] Requirements avoid prescribing a concrete implementation structure.
- [x] Success criteria are measurable and evidence-oriented.
- [x] Out-of-scope behavior is bounded by assumptions.
